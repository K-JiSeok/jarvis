작성일: 2026-10-12 · 대상: PHASE 17 커밋 (main)

> 표기: **[실제]** 운영 DB · 실제 네이버 API · 실제 Chrome 에서 확인 / **[모의]** 단위 테스트 / **[미실행]** 실행하지 않음 / **[제안]** 승인 전 제안 (구현 안 함) / **[미확인]** 존재 · 조건을 공식 문서로 확인하지 못함

## 결론 — 완전 자동화는 달성하지 못했다 (완료 선언하지 않음)

**자동으로 되는 것** [실제]
- 하루 1회 예약 실행 (사람 개입 없이 실제로 1회 실행됨)
- 키워드 후보 자동 발굴 (네이버 공식 API, 1,391개)
- 쿠팡 검색 수집 기록에서 상품 후보 자동 선정 · 등록 (36개, 재실행 시 중복 0)
- 판매 가능성 · 인증 · 브랜드 · 공급 사전 분류 (41개)
- V1 미리 보기 · 준비 상태 집계
- 실패 기록 · 중복 실행 방지 · 비정상 종료 정리

**여전히 막혀 있는 것**

| 막힌 것 | 원인 |
|---|---|
| 새 쿠팡 검색 결과 · 상품 페이지 수집 | 사용자 클릭 필요 — 서버 수집 · 자동 탭 열기는 쿠팡 약관 · 접근 제한 문제로 하지 않음 |
| 공급 원가 | 연결된 출처 없음 |

| 예약 실행 조건 | Chrome · JARVIS 서버가 켜져 있어야 함 (배포 서버 없음) |

## 1. 자동화된 기능과 아직 수동인 기능

| 단계 | 상태 | 방식 · 근거 |
|---|---|---|
| 자동 실행 시작 | **자동** [실제] | 확장 프로그램 `chrome.alarms` 1시간마다 → `POST /api/automation/run` → 서버가 마지막 예약 실행 뒤 20시간 안이면 건너뜀 (= 하루 1회). 웹 [자동 발굴 지금 실행] 도 같은 파이프라인 |
| 네이버 검색량 (추적 키워드) | **자동** [실제] | PHASE 14 함수 그대로 · 오늘 수집분 건너뜀 |
| 신규 키워드 후보 | **자동** [실제] | 네이버 키워드 도구 연관 키워드 (시드 = 추적 키워드 + 등록 상품의 쿠팡 카테고리 끝 단계) |
| 후보 → 추적 키워드 승격 | **수동 (버튼 1번)** | 승격 기준(검색량 · 관련성 등)은 새 사업 기준이라 정하지 않음 → 9-②, 14절 [제안] |
| 쿠팡 검색 결과 수집 | **수동** | 확장 프로그램 패널 [현재 검색 결과 수집]. 서버는 쿠팡에 요청하지 않음 (2-C) |
| 분석 대상 상품 선정 · 등록 | **자동** [실제] | 가장 최근 검색 수집 기록의 미등록 상품 전부 (사람의 체크박스 단계 없앰). 같은 기록 = 같은 멱등 키 → 재실행해도 중복 없음 |
| 상품 페이지 수집 (판매자 유형 · 평점 · 카테고리) | **수동** | 확장 프로그램 [JARVIS 수집] |
| 판매 가능성 · 인증 · 브랜드 · 공급 사전 분류 | **자동** [실제] | compliance-rules-v1 (5절) |
| 판매 불가 · 확인 완료 확정 | **사용자** | 자동 판단은 만들 수 없음 (DB CHECK) — 근거 메모 필수 |
| 공급 원가 · 물류비 | **불가** | 출처 없음 (6절) |
| Profit Engine | 기존 그대로 | 원가가 없어 새로 계산할 시나리오가 없음 — 있으면 V1 마진에 쓰임 |
| Score V1 미리 보기 · 준비 상태 | **자동** [실제] | 키워드별 연결 상품 전부 (최대 100), 점수 저장 안 함 (기존 정책) |
| 가격 · 리뷰 · 순위 이력 누적 | **반자동** | 날짜별 스냅샷 · 순위는 저장되지만 새 값은 쿠팡 화면 수집(수동) 때만 생김 |
| 오류 기록 · 재시도 | **자동** [실제] | 단계별 결과 저장 · 다음 실행이 상태 기준으로 실패분만 다시 함 |

## 4. 실제 상품 자동 수집 · 등록 결과 [실제]

- **입력:** 사용자가 PHASE 16 에 수집한 "실리콘 트레이" 쿠팡 검색 1페이지 기록 — 60칸, 미등록 상품 포함 원본 값
- **1회차**
  - 서로 다른 상품 41개 중 미등록 **36개 자동 등록**
  - 이미 등록 5 · 옵션 반복 칸 19 → **중복 제거 24**
  - 가격 · 정가 · 리뷰 · 배송 · 판매자 유형(검색 칸에 보인 것만) · 순위 · 광고 여부 저장. 출처 COUPANG_PAGE · A · 수집 시각 = 원래 수집 기록
  - 판매량 · 전환율은 만들지 않음. 평점은 검색 칸 반올림 값이라 상품 값으로 쓰지 않음 (기존 규칙)
- **2~7회차:** 신규 0 · 이미 등록 41 → 중복 생성 없음
- **DB:** 상품 41 = 쿠팡 ID 41개 고유 · 상품 스냅샷 41 · 순위 41
- **실패 처리:** 키워드마다 try/catch, 한 키워드 실패가 전체를 멈추지 않음 [모의 + 코드]. 실제 실패는 발생하지 않음

## 5. 판매 금지 · 인증 · 브랜드 위험 필터 검증 [실제 + 모의]

**규칙 (compliance-rules-v1)**
- 상품명 · 카테고리에서 "확인할 규정의 가능성"만 표시한다
- 출처 법령: 식품위생법 · 수입식품안전관리 특별법 · 어린이제품 안전 특별법 · 전기용품 및 생활용품 안전관리법 · 화장품법 · 건강기능식품법 · 의료기기법 · 생활화학제품법 · 상표법 · 디자인보호법 · 쿠팡 판매 금지 정책
- 영역별로 근거 · 출처 · 확인 시점 · 자동/사용자를 기록한다

**운영 결과 (41개):** REQUIRES_CERTIFICATION 30 · UNKNOWN 11 · BLOCKED 0 · CLEARED 0

**실제 상품명으로 찾은 오탐 · 누락 → 고침 (테스트로 고정)**
- 색상 "크림" · "크림베이지" → 화장품으로 판단 (오탐) → "크림" 단독 제외
- 식기건조대 · 물빠짐 · 펜 트레이 → 식품용 기구로 판단 (오탐) → 일반 단어(트레이 · 몰드 · 용기)는 문맥 단어가 있고 제외 단어가 없을 때만
- "푸드블럭 · 소분 냉동 몰드" 누락 → 추가
- 결과: 34 → 30

| 검증 | 결과 |
|---|---|
| BLOCKED · CLEARED 는 사용자만 | DB CHECK — 자동 판단이 만들면 23514 [모의 PGlite AU06 · AU07] |
| 사용자 BLOCKED → 일반 후보 제외 · 기록 유지 | 드라잉매트에 `[TEST]` 근거로 판매 불가 → 일반 후보 29 · "판매 불가로 제외된 상품 (1)" · 집계 1 [실제] |
| 근거 없는 판매 불가 · 확인 완료 거부 | "근거를 메모에 남겨야 합니다" [실제] |
| 자동 실행이 사용자 판단을 덮지 않음 | 다음 실행 keptUserDecision 1 · screened 40 [실제] |

| UNKNOWN 을 판매 가능으로 안 바꿈 | 일반 판매 후보 = 사용자 CLEARED 만 [모의] |
| 공급 가능성 | 41개 전부 UNKNOWN (출처 없음) |

## 6. 공급처 · 원가 자동 확보 가능 여부

**지금은 불가능하다.**
- 연결된 공급처 데이터 출처가 없다
- 원가를 만들어 넣지 않았다
- 원가 없는 상품은 수익성 확인 상품으로 표시하지 않는다 ("수익성 분석 완료 0")

현실적인 연결 후보 [미확인 · 승인 필요]

| 후보 | 이유 |
|---|---|
| ① 도매 플랫폼 공식 API (도매꾹 · 오너클랜 등) | 상품 검색 → 공급가 · 최소 주문 수량 |
| ② 해외 소싱 플랫폼의 공식 제휴 API | 1688 · 알리바바 계열 — 사업자 · 제휴 조건 필요 |
| ③ 사용자가 거래하는 공급처의 가격표 파일 · 링크 정기 동기화 | 형식을 받은 뒤 결정 |

어느 쪽이든 계정 · 약관 · 응답 형식을 확인한 뒤 Profit Engine 입력(`unit_cost_amount` · 통화 · 환율)에 출처와 함께 연결하는 것이 다음 단계다.

## 7. 판매량 · 성장 · 전환율 확보 가능 여부

1. **쿠팡 상품 후보를 사람 없이 확보할 경로 결정 (가장 큰 병목)**

     - **쿠팡 이용약관상 허용 여부를 사용자가 판단**해야 한다
   - 둘 중 하나 없이는 "새 상품 자동 탐색"이 지난 수집 기록 재사용에 머문다
2. **자동 의사결정 규칙 (V1 밖, 새 기준이라 미적용)**
   - 키워드 후보 자동 승격 조건 (예: 검색량 · 시드와 단어 공유 · 하루 최대 개수)

   - 전환율처럼 경쟁상품 단계에서 원천적으로 없는 요소를 V1 이 어떻게 다룰지
     - 현재: 9개 모두여야 판정 → 경쟁상품은 영원히 판정 불가
