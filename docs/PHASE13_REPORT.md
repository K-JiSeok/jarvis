## 핵심 결과

```text
키워드 등록 → 검색량 파일(/import) → 상품 · 가격 이력 · 순위 → 경쟁상품 연결(화면) → 수익성 입력(화면)
  → 상품 상세 Score 미리 보기: 요소마다 "점수 / 100 ✓" 또는 "— 데이터 부족" + 부족한 데이터 목록   ✅ [확인]
```

| 상품 | 맥락 키워드 | 계산된 요소 | 부족한 데이터 [확인] |
|---|---|---|---|
| T1 (검색량 없음 · 경쟁 미연결) | 캠핑의자 A | 3/9: 리뷰 장벽 48.3 · 마진 53.31 · 안정성 100 | 검색량 · 판매량 · 판매량 이력 · 경쟁 지표 · WING · 전환율 |
| T2 (검색량 10,000 + 경쟁 A·B·C) | 캠핑의자 B | 6/9: 수요 60 · 경쟁 83.64 · WING 57.78 · 리뷰 42.5 · 마진 78.25 · 안정성 100 | 판매량 · 판매량 이력 · 전환율 |
| T3 (검색량 10,000 · +12% + 경쟁 A·B·C) | 캠핑의자 C | 6/9: 수요 **62.4** · 경쟁 83.64 · WING 57.78 · 리뷰 42.5 · 마진 100 · 안정성 100 | 판매량 · 판매량 이력 · 전환율 |

- 세 상품 모두 화면 값 = 엔진 값 = 손 계산 값 (아래 3절) [확인]
- 최종 판정은 세 상품 모두 **"계산 불가"** — V1 규칙대로 9개가 다 있어야 판정한다
- 데이터를 넣으면 해당 요소가 살아나는 것을 확인했다
  - 검색량 → 수요
  - 증감률 → 수요 가감
  - 경쟁상품 연결 → 경쟁 · WING · 리뷰
  - 수익성 → 마진
  - 가격 3회 → 안정성
- **판매량 · 판매 성장률 · 전환율 3개는 실제 출처가 없어 비어 있다** (지시대로 추정하지 않음)

## 1. Score 9개 요소 연결 상태 (실제 코드 기준)

엔진: `src/lib/scoring/engine.ts` (score-engine-v1)
입력 수집: `src/lib/repositories/opportunity.ts` `buildScoreInput()`
점수 공식 · 가중치 · 정규화 · 판정 기준은 **변경 없음**.

| 요소 (가중치) | 엔진이 읽는 값 | DB 테이블 · 필드 | 지금 상태 [확인] |
|---|---|---|---|
| 수요 (15) | 맥락 키워드 월 검색량 + 증감률 (±10점 가감) | `keyword_snapshots.search_volume` · `search_growth_rate` (`v_keyword_latest` 선택값) | **계산 가능** — 검색량 파일 · API 를 넣으면 |
| 판매량 (15) | 대상 · 활성 경쟁상품의 실제(우선)/추정 판매량, 집계 기간 → 30일 환산 중앙값 | `product_snapshots.sales_actual` · `sales_estimated` · `sales_period_days` | **계산 불가** — 실제 출처 없음 |
| 판매 성장 (10) | 같은 종류 판매량 이력 2회 이상 (7일 이상 간격, 90일 안) | 위와 같음 (스냅샷 이력) | **계산 불가** |
| 경쟁 난이도 (15) | ① 키워드 상품수/검색량 ② 브랜드 집중도 ③ 내 판매가 ÷ **활성 경쟁상품** 가격 중앙값 — 있는 지표 평균 | `keyword_snapshots.competition_intensity` · `brand_concentration` · `competitors` → 경쟁상품 `product_snapshots.price` · 대표 시나리오 `profit_scenarios.sale_price` | **계산 가능** — 경쟁상품을 연결하면 ③ 으로 |
| WING 진입 (10) | 키워드 WING 비율, 없으면 판매자 유형을 아는 활성 경쟁상품 3개 이상 중 WING_SELLER 비율 | `keyword_snapshots.wing_ratio` · 경쟁상품 `seller_type_observed` | **계산 가능** — 경쟁상품 3개 이상 연결하면 |
| 리뷰 장벽 (10) | 활성 경쟁상품 리뷰 수 중앙값, 없으면 키워드 평균 리뷰 | 경쟁상품 `review_count` · `keyword_snapshots.average_reviews` | **계산 가능** — PHASE 12 의 1페이지 평균 리뷰만으로도 |
| 전환율 (5) | 대상 · 경쟁상품 전환율 중앙값 | `product_snapshots.conversion_rate` | **계산 불가** — 실제 출처 없음 (WING) |
| 마진 (15) | 대표 수익성 시나리오의 현재 계산 순이익률 | `profit_scenarios` (is_primary) · `profit_calculations` (is_current) | **계산 가능** (PHASE 6 연결 그대로) |
| 시장 안정성 (5) | 최근 180일 가격 3회 이상의 변동계수 | 대상 `product_snapshots.price` 이력 (제외 행 빼고) | **계산 가능** — 날마다 수집하면 |

### 1-1. 엔진이 쓰지 않는 수집값 [확인]

| 수집값 | 상태 | 이유 |
|---|---|---|
| 키워드 평균 가격 (`average_price`) | V1 입력 아님 | 경쟁 난이도는 "연결한 경쟁상품" 가격을 쓴다 |
| 로켓 비율 (`rocket_ratio`) | V1 입력 아님 | WING 진입은 WING 판매자 비율을 쓴다. 로켓 비율 ≠ WING 비율 |
| 검색 결과에 함께 나온 상품 | 직접 입력 아님 | 상품 상세에서 사용자가 "경쟁상품 후보"를 골라 연결해야 `competitors` 로 들어간다 (PHASE 12 기능) |

- 위 값을 점수에 쓰려면 정규화 · 입력 정의를 바꿔야 한다. 이번 PHASE 금지사항이라 **바꾸지 않았다**
- 단위 테스트로 "값이 있어도 점수 변화 없음"을 고정했다

### 1-2. 이번에 바꾼 연결

엔진 · 입력 수집은 바꾸지 않았다. 바꾼 것은 화면과 검색량 입력 경로뿐이다.

- **상품 상세 Score 카드:** 9개 요소 상태 요약을 추가했다
  - 요소마다 `점수 / 100 ✓` 또는 `— 데이터 부족`
  - "최종 판정: 계산 불가 (N개 요소 데이터 부족)"
  - "부족한 데이터" 목록
  - 모두 `ScoreResult` 그대로 그린다. 화면에서 따로 계산하지 않는다
- **경쟁 연결:** 새 모델 없이 기존 `competitors` 를 그대로 쓴다. 최소 연결이 이미 있어 추가 구현이 필요 없었다
- **수익성 연결:** 기존 대표 시나리오를 그대로 쓴다. 이미 연결돼 있어 추가 구현이 필요 없었다

### 2-3. 네이버 검색광고 API — 공식 명세로 확인한 것 [확인]

출처: `github.com/naver/searchad-apidoc`
- `gh-pages/assets/json/ncc-keywordstool.json` (공식 Swagger 명세)
- `python-sample/examples/signaturehelper.py` · `ad_management_sample.py`

| 지시서 질문 | 확인 결과 |
|---|---|
| 1. 원하는 검색량을 얻을 수 있나 | 예. `GET https://api.searchad.naver.com/keywordstool?hintKeywords=…&showDetail=1` → `keywordList[]` |
| 2. 월간 PC/모바일 검색량 | `monthlyPcQcCnt` · `monthlyMobileQcCnt` = **최근 30일** 조회수 합. 10 미만이면 문자열 `"<10"` |
| 3. 경쟁 · 클릭 | `monthlyAvePcClkCnt` · `monthlyAveMobileClkCnt` · `monthlyAvePcCtr` · `monthlyAveMobileCtr` · `plAvgDepth` · `compIdx`(low/mid/high, PC 광고 기준) |
| 4. 인증 | 헤더 `X-Timestamp`(ms) · `X-API-KEY` · `X-Customer` · `X-Signature` = Base64(HMAC-SHA256(secret, `"{timestamp}.{METHOD}.{uri}"`)). 키는 검색광고 관리자센터 → 도구 → API 사용 관리에서 발급 |
| 5. 요청 제한 | 숫자로 공개된 한도 없음. 초과 시 오류 코드 1016 "너무 많은 접속을 시도 하였습니다" |
| 6. 한국어 키워드 | 명세 예시가 한국어 (`꽃배달,flower,화환`). `hintKeywords` 는 쉼표 구분 **최대 5개** |
| 7. `keyword_snapshots` 매핑 | `search_volume = PC + 모바일` · source `OFFICIAL_API` · confidence `A` · 이전 달 값은 응답에 없음 |

명세 외 사항 [제안 · 미검증]

- 응답 키워드는 공백 없이 온다는 것이 사용 사례에서 보인다. 매칭은 공백 제거 · 소문자로 하고, 요청도 공백을 빼서 보낸다
- 실제 키가 생기면 검증해야 한다

### 2-4. 매핑 원칙 (구현)

| 상황 | 처리 |
|---|---|
| PC 또는 모바일 값이 `"<10"` | **NULL** (모름). 0 으로 만들지 않는다 (0 = 실제 0) |
| 요청한 키워드가 응답에 없음 | 저장하지 않음 + 사유 기록 |
| 연관 키워드 (요청하지 않은 것) | 버림 (자동 키워드 등록 없음) |
| 증감률 | 같은 키워드의 이전 `OFFICIAL_API` 스냅샷(25~40일 전)이 있을 때만 이전 검색량으로 넘김 → **기존** `normalizeKeyword` 공식 `(현재−이전)/이전` |
| 클릭 · CTR · compIdx | 대응 컬럼이 없어 수집 기록(payload)에만 |
| 키 | `NAVER_SEARCHAD_API_KEY` · `NAVER_SEARCHAD_SECRET_KEY` · `NAVER_SEARCHAD_CUSTOMER_ID` (`.env.local`, 서버 전용 · 코드에 없음) |
| 키가 없을 때 | 호출하지 않고 안내만 (키워드 상세 버튼에서 확인 [확인]) |
| 확장 프로그램 출처 | 확장 프로그램이 `OFFICIAL_API` 출처를 보내면 `/api/ingest` 가 거부 (서버 수집기 전용) [확인: 단위 테스트] |

주의: 네이버 검색량은 **네이버 검색** 수요다. 쿠팡 검색 수요가 아니다. 값 자체는 공식 API 원본이라 A 지만, 쿠팡 수요의 대리 지표라는 점을 화면에 적었다.

## 3. 실제 Score Preview — 3개 상품 [확인]

### 3-1. 시험 데이터

모두 `/import` 와 상품 상세 화면으로 넣었다.

- **상품 6개:** T1 · T2 · T3 (대상), 경쟁 A · B · C (모두 `[TEST]`)
- **가격 이력** (상품 데이터 파일, T1~T3): 2026-09-10 10,000 · 09-20 10,200 · 10-01 9,800원
- **경쟁상품 값:**
  - A 11,000원 · 리뷰 500 · WING 판매자
  - B 12,000원 · 1,500 · 쿠팡 직매입
  - C 9,000원 · 3,000 · 로켓그로스 판매자
- **순위 파일:** 각 키워드에 대상 1위, A · B · C 2~4위
- **경쟁상품 연결:** T2 · T3 상세의 "경쟁상품 후보"에서 A · B · C 를 SIMILAR 로 직접 등록 (화면 버튼)
- **수익성:** 상세의 수익성 계산기에서 저장. 판매가 10,500 · 물류 1,500 · 수수료 10.8% · 원가 T1 6,000 / T2 5,000 / T3 3,000
  - 순이익률 T1 17.77% · T2 27.30% · T3 46.34%

### 3-2. 화면 값 ↔ 손 계산

| 요소 | T1 화면 | T2 화면 | T3 화면 | 손 계산 근거 (RULES 구간) |
|---|---|---|---|---|
| 수요 | — | 60 | 62.4 | 10,000 → 5,000(50)~20,000(80) 구간 = 60 · T3 +0.12×20 = +2.4 |
| 판매량 | — | — | — | 판매량 없음 |
| 판매 성장 | — | — | — | 판매량 이력 없음 |
| 경쟁 난이도 | — | 83.64 | 83.64 | 10,500 ÷ 중앙값 11,000 = 0.9545 → 0.9(100)~1(70) |
| WING 진입 | — | 57.78 | 57.78 | 3개 중 WING 1 = 33.3% → 0.2(40)~0.5(80) |
| 리뷰 장벽 | 48.3 | 42.5 | 42.5 | T1: 키워드 평균 리뷰 1,113.3 · T2/T3: 경쟁 중앙값 1,500 → 1,000(50)~3,000(20) |
| 전환율 | — | — | — | 전환율 없음 |
| 마진 | 53.31 | 78.25 | 100 | 17.77% → 0.1(30)~0.2(60) · 27.30% → 0.2(60)~0.3(85) · 46.34% ≥ 0.4 |
| 시장 안정성 | 100 | 100 | 100 | 변동계수 1.6% ≤ 2% |
| **최종 판정** | 계산 불가 (6개 부족) | 계산 불가 (3개 부족) | 계산 불가 (3개 부족) | 9개가 다 있어야 판정 |

T1 → T2 → T3 로 데이터가 늘수록 요소가 하나씩 살아났다.
- 검색량을 넣으니 수요가 계산됐다
- 증감률을 넣으니 수요에 +2.4점이 더해졌다
- 경쟁상품을 연결하니 경쟁 · WING 이 계산되고, 리뷰 장벽이 키워드 평균에서 경쟁 중앙값으로 바뀌었다

같은 입력을 `npm run test:score` 의 PHASE 13 테스트 5개로 고정했다 (엔진 값 = 손 계산).

## 4. 경쟁분석 연결 [확인]

- **연결 경로:** 키워드 → `keyword_product_ranks` → 상품 상세 "경쟁상품 후보" (같은 키워드 · 최근 수집일) → **사용자가 관계 유형을 골라 등록** → `competitors` → 경쟁상품의 최신 `product_snapshots`
  - 엔진은 `competitors` 의 활성 관계만 읽는다
- 같은 검색 결과에 등록 상품이 여러 개여도 **자동으로 경쟁상품이 되지 않는다** (PHASE 12 원칙 유지). 연결한 뒤에야 다음이 반영된다

| 반영되는 값 | 쓰는 요소 | 실제 결과 |
|---|---|---|
| 경쟁상품 수 | WING 진입 최소 표본 3 | 3개 → 계산 (2개면 미계산: 단위 테스트) |
| 경쟁상품 리뷰 | 리뷰 장벽 (키워드 평균보다 우선) | 중앙값 1,500 → 42.5 |
| 경쟁상품 가격 | 경쟁 난이도 가격 비율 | 중앙값 11,000 → 83.64 |
| 경쟁상품 판매자 유형 | WING 진입 | WING 1/3 → 57.78 |

- 광고 여부는 V1 엔진 입력이 아니다
- 쿠팡 전체 상품 수가 없어 "상품수/검색량" 지표는 아직 계산되지 않는다. 검색량만 있어서는 안 된다

## 5. Profit 연결 [확인]

## 11. 발견된 문제 (실제 사용 중 발견한 것만)

1. **앱 브라우저 로그인 만료.** 시험 중 JARVIS 세션이 만료돼 사용자가 다시 로그인했다.
2. **`/import` 화면을 연 직후 유형 선택이 먹지 않음.** 화면이 준비되기 전에 누르면 "상품 데이터"로 남는다. 사람이 누를 때는 거의 일어나지 않지만, 파일 분석 전에 유형을 다시 확인하게 하면 안전하다 [제안].
3. **파일 출처는 한 job 에 하나다.** 지시서 6-A 의 "행마다 source/confidence" 는 지금 `/import` 구조에서 화면 선택 1개로 대신한다. 또 `/import` 출처 목록은 설계상 `OFFICIAL_API` 를 고를 수 없다 (파일은 API 응답임을 증명할 수 없음). 네이버 키워드 도구 화면에서 내려받은 파일은 "직접 입력"으로 넣고 신뢰도를 사용자가 고른다.
