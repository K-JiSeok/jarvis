## 1. 질문: 검색 결과 50개 중 몇 개를 골라 등록해야 하나

**고르지 않아도 됩니다.**
- [현재 검색 결과 수집]만 누르면, 다음 자동 실행의 "상품 자동 등록" 단계가 그 검색 결과의 미등록 상품을 최대 100개까지 전부 등록합니다(PHASE 17).
- [실제] 나무도마 수집분(칸 61개)은 이미 자동 등록됐고, 상품이 41개에서 51개가 됐습니다.
- 체크박스 등록은 특정 상품만 즉시 넣고 싶을 때만 씁니다.
- 판매량 추정까지 하려면 등록된 상품 페이지를 열어 리뷰를 [최신순]으로 바꾼 뒤 수집하면 됩니다. 수집할 상품은 /discover "오늘 수집할 상품 페이지" 칸에 나옵니다.

## 2. 매일 오전 추천 — 동작 방식

```
매일 08:00 (앱이 몇 분 분산 → 08:13 전후)
  Claude 앱 예약 작업 "JARVIS 매일 오전 상품 3개 추천" 실행 (이 PC)
   1. npm run picks:candidates      — 추천 후보 묶음 만들기 (읽기만)
   2. Claude가 후보를 보고 최대 3개 선정 · 근거 · 위험 · 소싱 가이드 작성
   3. npm run picks:save            — daily_picks 에 오늘 날짜로 저장
   4. 휴대폰 알림 (Remote Control 연결 시)
  → /discover 맨 위 "오늘의 추천"에서 확인 · [후보로 선택] 또는 [관심 없음]
```

- **후보 조건 (스크립트):**
  - 판매량 추정과 판매가가 있어야 합니다.
  - 검토 제외 · 판매 불가 · 판매 중단 상품은 뺍니다.
  - 최근 14일 안에 추천한 상품은 뺍니다.
  - 단품 비추천(저가)은 묶음으로 가능한 것만 남깁니다.
  - 정렬: 가격 구조 등급 → 추정 월 매출.
- **선정 기준 (Claude):**
  - 가격 구조 적정을 먼저 고르고, 거의 같은 상품은 하나만 고릅니다.
  - 판매 근거가 강한 순서로 고릅니다.
  - 수입 인증 필요 여부와 할인 종료 뒤 위험을 함께 적습니다.
  - 기준에 맞는 것이 없으면 억지로 3개를 채우지 않습니다.
- **추천은 매입 결정이 아닙니다.**
  - [후보로 선택]을 누르면 기존 관심상품(WATCHING)에 들어가 PHASE 21 소싱 흐름으로 이어집니다.
  - [관심 없음]은 14일 동안 추천에서 빠집니다.
- **실행 조건:** 이 PC와 Claude 앱이 켜져 있어야 합니다. 꺼져 있었으면 다음에 앱을 켤 때 실행됩니다.

## 3. 구현

| 항목 | 내용 |
|---|---|
| DB `daily_picks` | 날짜 · 순위(1~3) · 상품 · 근거 · 위험 · 소싱 가이드 · 판단에 쓴 수치 사본 · 선정 주체(CLAUDE_SCHEDULED / CLAUDE_MANUAL / RULE) · 응답 상태 |
| DB 제약 · 보안 | 같은 날 같은 순위 1개 · 복합 FK · RLS 4정책. 원격 적용 완료 |
| `scripts/picks/candidates.mjs` | 서버 전용 키로 **이 사용자 데이터만** 읽습니다. 기존 순수 함수를 그대로 씁니다: 판매량 추정 · 단위 경제성 · 카테고리 추정 · 단계 · 중국어 검색어 |
| | 소유자가 여럿이면 `--owner` 없이는 멈춥니다. 키는 출력하지 않습니다 |
| `scripts/picks/save.mjs` | 그 사용자의 상품인지 확인하고, 후보 파일로 상품 ID와 판단 수치를 채워 저장합니다 (손으로 옮겨 적지 않음) |
| `scripts/picks/lib.mjs` | 환경변수 읽기 · 소유자 확인 |
| /discover "오늘의 추천" | 3개 카드 (판매가 · 추정 판매 · 월 매출 · 쓸 수 있는 원가 · 근거 · 위험 · 1688 검색어 · 묶음 제안) · [후보로 선택] / [관심 없음] · 지난 추천 14일 |
| 예약 작업 | `jarvis-daily-picks` (매일 08:00, 사이드바 "Scheduled") |

- 마이그레이션: `supabase/migrations/20261014120000_daily_picks.sql`
- 그 밖에 바뀐 파일: `src/lib/repositories/picks.ts` · `src/components/discover/picks-{panel,forms}.tsx` · `src/app/discover/{actions,page}.tsx` · `src/types/database.ts` · `.gitignore` (`scripts/picks/out/`)

## 8. 추가 작업 (같은 날)

### 8-1. 검색 수집 확인 [실제]
- 오늘 수집된 키워드 9개 (각 약 60칸): 나무도마 · 방풍비닐 · 보온병 · 식탁매트 · 젓가락 · 차량용청소기 · 캠핑용품 · 케이크토퍼 · 코일매트
- **캠핑랜턴은 저장된 기록이 없습니다** — 다시 수집이 필요합니다.
- 자동 실행으로 미등록 상품이 자동 등록돼 **상품 41개 → 492개**가 됐습니다.
- 새 상품은 리뷰 수 기록이 한 번뿐이라 판매량은 아직 추정되지 않습니다 (479개 미추정). 상품 페이지를 [최신순]으로 수집하거나 7일 뒤 다시 수집해야 합니다.

### 8-2. 상품 492개에서 화면 오류 수정 [실제]
- 원인: 상품 ID 수백 개를 한 번에 요청 주소에 넣어 16KB 한도를 넘었습니다.
- 고친 곳: 상품 목록의 키워드 순위 조회, 판매 추정, 상품 정보 조회. 100개씩 나누거나 전체를 읽은 뒤 메모리에서 거릅니다.
- `/discover` 가 492개에서도 정상으로 열리는 것을 확인했습니다.
- "오늘 수집할 상품 페이지"는 가격 구조가 좋고 누적 리뷰가 많은 순으로 바꿨습니다 (예: 텀블러 · 캠핑의자 · 무선 청소기).

### 8-3. PC가 8시에 꺼져 있었을 때
- Claude 앱 예약 작업은 앱이 꺼져 있던 시간에 놓친 작업을 **앱을 켜면 바로 실행**합니다.
- 예약 작업 지시를 보강했습니다.
  - 늦게 돌아도 "오늘(KST)" 기준으로 고릅니다.
  - 오늘 이미 예약 추천(CLAUDE_SCHEDULED)이 있으면 다시 고르지 않습니다 (중복 방지). 후보 파일에 `todayPicks` 를 추가해 이를 판단합니다.
  - 추천 스크립트는 JARVIS 웹 서버(localhost:3000)가 꺼져 있어도 동작합니다 (DB를 직접 읽음).
- **남은 조건: PC를 켤 때 Claude 앱이 자동으로 켜져야 합니다.** 지금 Windows 시작 프로그램에는 Claude 앱이 없습니다 [실제 — 읽기만 확인]. 시스템 설정이라 제가 바꾸지 않았고, 사용자가 등록해야 합니다.
  1. 시작 메뉴에서 Claude 앱 아이콘을 오른쪽 클릭 → [자세히] → [파일 위치 열기]
  2. Win + R → `shell:startup` 입력 → 열린 폴더에 1의 Claude 바로가기를 복사
  3. (선택) Chrome 도 같은 방식으로 넣으면 JARVIS 확장 프로그램의 매시간 자동 발굴도 함께 돕니다
